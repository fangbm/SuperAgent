# M6 故障注入与安全审查

日期：2026-11-03。状态：**当前已实现模块的 M6 本地验收完成**。新增 17 项故障与安全测试，并将既有恢复测试纳入独立入口。没有主动在真实 QQ、GitHub 或模型服务上注入故障，也没有新增真实平台消息或状态写入。

## 复现与结果

```powershell
pnpm test:m6
pnpm check
pnpm audit --prod --json
pnpm audit --json
```

- `test:m6` 自动构建后执行 73 项专项测试，全部通过，包含真实本地 HTTP、文件 SQLite、两个数据库连接、实际子进程终止以及模拟网关。
- 完整 `check` 通过 215 项 Node 测试、6 组 Python/SQLite 参考验证、类型正反例、依赖与私有边界，以及 45 个 M0 冻结文件校验。
- 生产依赖审计覆盖 10 个依赖，全依赖审计覆盖 34 个依赖；各严重级别已知漏洞计数均为 0。这是本次注册表审计结果，不表示不存在未知漏洞。
- 测试只使用临时数据库、测试密钥、受控适配器和本机 HTTP 服务。依赖审计访问软件注册表；未向真实平台执行故障操作。

机器记录见 [m6-local-2026-11-03.json](evidence/m6-local-2026-11-03.json)。CI 的既有 `pnpm check` 已包含新目录；本记录证明本机 Windows 验证，不能替代远端 Linux/Windows CI 的实际结果。

## 故障矩阵

| 路径 | 注入 | 验证结果 | 证据层次 |
| --- | --- | --- | --- |
| QQ Gateway 重连 | 断线、无效 session、丢失心跳、永久 intent 拒绝 | 从持久序号 Resume；无效会话重新 Identify；永久拒绝停止 | 模拟 WebSocket，真实 Host/SQLite 集成 |
| Gateway 慢提交与洪峰 | 阻塞提交，超过待处理上限 | 有界关闭；先等待活动提交完成，再恢复；未提交项不推进序号 | 新增模拟网关测试 |
| 事件幂等 | 重复/旧序号，已签名回调重复与重启 | 无重复分发、源事件或首次任务；失败事务不 ACK | 新增网关测试与既有 SQLite 回归 |
| QQ 认证限流 | token 端点 HTTP 429 | 最多 3 次安全重试；期间消息 POST 为 0；耗尽转人工处理 | 真实本地 HTTP |
| QQ 已发送后超时 | HTTP 头已返回、响应体悬挂；实际子进程被终止 | unknown 跨重启保持，不重发 POST | 本地 HTTP、实际进程终止、文件 SQLite |
| 并发投递与晚回包 | 两个 SQLite 连接竞争，Host 超时后才返回 accepted | 仅一个发送；晚回包不能把 unknown 改成成功 | 两个数据库连接、模拟适配器 |
| QQ 权限或绑定丢失 | HTTP 403；已准备后变更收件人绑定 | blocked，无格式降级重发；绑定变化在网络调用前阻止 | 本地 HTTP、数据库变更 |
| 撤回恢复 | unknown、租约过期、超出两分钟、绑定变化 | 不重复 DELETE，过期不调用；半日报保持 | 既有撤回 SQLite 回归 |
| GitHub 故障恢复隔离 | QQ 和其他仓库存在过期租约 | 当前 GitHub Sync 不更改其他账本 | 新增 SQLite 测试 |
| 模型限流 | 连续两次 HTTP 429，期间仍有新事件入库 | 原文保留，退避后原批次恢复，领域效果不重复 | 真实本地模型 HTTP 服务 |
| 模型权限丢失 | HTTP 401 | 不重试，任务 dead_letter，原始证据保留 | 真实本地 HTTP |
| Worker 中断与租约 | 终止实际子进程，旧 worker 延迟返回 | 恢复未完成任务；过期 worker 不能提交替代者的结果 | 既有实际进程终止与 SQLite 回归 |

M6 入口包含以上新增测试，以及既有 `qq-gateway`、`qq-source`、`qq-delivery`、`qq-card-retirement`、`m3-recovery`、`crash-bulk` 和 `m5-actions` 回归。完整测试另覆盖 GitHub correlation 对账、跨项目证据拒绝和报告封存。

## 安全审查与修复

| 发现 | 修复与回归 |
| --- | --- |
| Gateway 慢提交时队列无长度上限 | 默认上限 256，超过上限断开并从已持久提交点恢复，配置必须是正整数 |
| Delivery 只在构造时验证绑定 | 每次发送前重核对绑定与当前授权，变化时不调用插件 |
| GitHub Sync 恢复 SQL 可修改其他连接器租约 | 按当前 repository 的同步 payload 限定恢复范围 |
| 轮换访问密钥后旧 Web 会话仍有效 | 事务内撤销该账号会话，相同密钥和其他账号会话保持 |

同时验证了以下既有安全边界：

- Web 登录失败限流；Origin、Host、CSRF、请求体大小；角色降级和跨项目访问拒绝。伪造 Host 使用原始 HTTP 客户端验证，避免 fetch 自行改写该头造成假阳性。
- 游标绑定账号、项目、报告修订和有效期；签名被修改后拒绝。
- QQ 玩家提示词注入经过真实 Source→Ingress→Worker→本地模型 HTTP，仍作为候选消息的文本字段；没有工具调用或外部投递。原始 OpenID、AppSecret、伪名化密钥不进入模型请求。
- QQ、GitHub、模型的带凭据 HTTP 请求均拒绝重定向；第二个本机服务未收到请求。自由格式平台错误正文不进入持久投递记录。
- 所有写入仍需显式开启，GitHub 目标仍须私有；连接器只经 SDK Host 访问能力，不读取数据库。没有增加群发言能力。

设计与兼容性见 [ADR 0010](ADR/0010-m6-fault-and-security-boundaries.md)。

## 覆盖边界

M6 的“通过”指上述本地可重复故障与安全审查；先前真实 QQ/GitHub 的成功路径仍以各轮独立验收记录为准。模拟网关通过不等于真实网络故障恢复已获平台保证，提示词隔离测试也不表示所有模型输出都天然可信。

未进行：真实平台账号撤权/限流故障、真实 QQ 心跳断线及平台历史回放补齐、多机分布式部署、持续数小时或数天的压力测试、渗透测试认证。M4 Discord/Steam 实际采集、P0 调度、全量 QQ 群权限、生产隐私保留周期仍未交付或未确认。M6 不将这些范围改记为已完成，也不部署服务。
