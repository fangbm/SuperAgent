# 通知分流与 P0 实时告警 ADR (v0.7)

## 决策及适用范围

**唯一允许的自动即时 QQ 通知是 P0 Bug 告警。** 其他 Bug（P1/P2/P3/unknown）、Steam 差评、玩家建议，统一进入北京时间 18:00 和次日 00:00 的 Markdown + Keyboard 半日报；Web 控制台随时可查看数据，不属于对开发者主动推送。

单条高热度差评或热门建议不能因热度高而绕过规则发送即时通知。如果 Steam 差评揭示了满足 P0 标准的真实 Bug，则由该 Bug 发出 P0 通知，而非由差评本身发出。

## 判定及执行链路

1. 接收消息：事件先持久化，**无论是否 P0 都不阻塞采集**。
2. Admission 标记 `urgent_candidate` 只触发快速分析，不代表已经定级 P0，也**不得直接通知**。
3. 领域服务根据证据、规则和项目 P0 定义确定 Issue.severity=P0；模型只能提案并附来源证据。不确定时先进行快速复核或人工紧急审核。
4. `NotificationPolicyV1.decide` 只允许 `kind=defect && severity=P0` 返回 `p0_realtime`，并在数据库事务中更新/创建 `p0_incidents`、唯一代际 `p0_alerts` 及持久发送任务。其他返回 `digest_only`；不得创建任何非 P0 通知发送任务。
5. P0 专用高优先队列使用 QQ C2C 的 `P0AlertDeliveryPluginV1.sendP0Alert`，不等待 18:00/00:00，发往授权开发者。失败保留 Web 告警状态。
6. 同一活跃 incident 的重复玩家反馈只更新证据和统计，不生成第二次主动通知。仅重大新影响、修复后再次确认发生或开发者明确重新告警才增加 `alertGeneration`。修复关闭 incident 后复发新开 incident，防止原工单长期复发被静默吞掉。
7. P0 的反馈仍进入原窗口半日报，并注记 `已实时告警` 与告警状态；P0 不应该从报告统计中消失。半日报作为归档/概览消息仍按原计划发送，不因 P0 实时发送额外第二份报告。

## P0 标准参考（需要项目层确认和调优）

例如：广泛或可确认的存档不可恢复损坏、严重账号安全问题、造成重大服务不可用的崩溃。P0 表示高紧急程度，而不是模型给了 0.99 的分数；不能根据“差评”“多人反馈”自动升级 P0，也不能因分类不确定而直接发送误报。P0 快速评估要能跳过普通批处理排队，不能等 60s/120s flush。

## 频控与对账

- `incidentId + alertGeneration + recipientRef` 为同一 P0 投递幂等键；需要跨进程锁和持久 outbox 防止并发重复发送。
- `delivery_id` 和 `external_operations` 的 `operation_id` 必须预先持久化。已发请求遇到超时/重启视为 `unknown`；未获可靠平台幂等/查询支持时**不盲目重发**，由控制台标记人工确认。`accepted` 仅表示平台受理。
- 同一活跃 incident 在本地做去重，重复反馈**不刷新冷却时间来屏蔽真正的新 incident**；重大升级变更必须存入审计并升级 `alertGeneration`。
- QQ 主动消息权限不足时，P0 在 Web 控制台保留紧急未送达告警，状态 `blocked`，不得悄悄降级为对群发言。
- 开发者查询 `/bugs`、点击 `Details`、`Fixed` 等明确请求后产生的**交互回复**不属于主动推送禁令；仍要求身份校验和 QQ 回调权限。

## 半日报固定时段与互斥约定

- 每日 18:00 统计 `[当天00:00,当天18:00)`；每日 00:00 统计 `[前日18:00,当天00:00)`，均按 Host `received_at`。
- 在截止后完成分析的反馈按既有修订机制更新归档，不额外推送非 P0 消息；下一份报告可带修订提示。
- P0 的即时投递不会单独消费事件，不能影响按时间窗口生成报告的统计。
- 半日报底部始终为 `查看 Bug` / `查看建议` / `查看 Steam 差评`。

## 验收用例

| 场景 | 预期 |
|---|---|
| P1 新 Bug / 新 GitHub Issue | 保存/同步，不实时 QQ 投送，半日报展示 |
| Steam 差评 1 星且有热度 | 不实时推送，半日报展示原文 |
| 玩家建议提取 / GitHub 新 enhancement | 不实时推送，半日报展示 |
| 新消息标记 urgent_candidate 但未确认 P0 | 不推送；进入快速复核 |
| 确认为 P0 的 Bug | 创建唯一实时告警及外部操作任务，Web 同时可见 |
| 相同 P0 被 20 个玩家重复报告 | 原文和统计全部保留，仅首次确认后生成单次告警 |
| P0 获重大新证据 | 按审计规则增加 generation，再发一次告警 |
| 已 Fixed 的 P0 再次复发 | 新 incident 允许独立实时告警 |
| P0 发送超时、结果不明 | unknown，不盲目重发；Web 有明确状态 |
| 到 18:00 / 00:00 | P0、非 P0、差评、建议完整统计，P0 标注已告警与状态 |
| QQ 按钮查询详情 | 仅用户请求的回执，非主动非 P0 通知 |
