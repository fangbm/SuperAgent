### 人工反馈：报告 Markdown 未渲染

用户打开演示页后反馈 Markdown 未渲染。原因是报告摘要直接放进 pre 标签，未调用 Markdown 解析器。现由 Web 层的 CommonMark AST 允许列表生成派生 HTML，支持标题、列表、加粗、引用与代码排版；玩家原文继续按文本节点原样显示。渲染接口沿用账号、项目和精确修订权限，HTML/图片/不安全链接不会成为活动内容，原报告 JSON 和 seal 不变。设计见 [ADR 0008](ADR/0008-web-report-markdown.md)。

新增 3 项测试覆盖 HTML 结构与输入处理，以及真实前端脚本在模拟 DOM 中请求实际本地 HTTP 接口、点击打开报告和原文；同时检查旧修订渲染稳定、401/403/404 和原文保真。完整检查通过 184 项 Node 测试及 6 组参考套件。模拟 DOM、HTML 解析与真实 HTTP 分开记录，不替代可见浏览器验收。

更新演示服务前通过 SQLite backup API 备份原演示库，保留原端口、数据库及既有会话；端口 51510 已提供新版脚本、CSS 和渲染接口。实际 HTTP 返回 200，报告派生 HTML 包含 1 个主标题、4 个二级标题和 9 个列表项，报告 seal 与备份一致。用户刷新并复核后明确确认“显示和操作都正常”，本轮 Web 客户端人工验收通过；没有将该确认记为自动视觉测试，也不据此新增具体状态操作的数据库审计证据。状态写入的持久化仍由本地 HTTP 回归与真实 GitHub 读回分别证明。见 [Web Markdown 修复证据](evidence/m5-web-markdown-2026-11-03.json)。
