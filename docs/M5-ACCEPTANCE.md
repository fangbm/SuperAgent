### 第二、三轮真实复测

用户要求“再测一下”后，第二轮限三条查询回复，只接受当前步骤对应的新按钮。北京时间 10:16:04 / 10:16:07 / 10:16:10，Bug 列表、详情、原文各一次 accepted。详情与原文使用外层事件 ID 进行被动回复，两次 ACK 均 HTTP 200；三步后进程退出。用户截图证明原文实际显示，同时发现底部暴露长 `/open` 分页命令。用户随后澄清仅修底部指令，原文和来源无误。

原因是原文页强制纯文本，使发送器将按钮展开成命令。现改为 Markdown 字面文本模式：存档、请求中的原文和分页仍使用原始字符，只在发送层转义 Markdown 控制字符并保留换行；分页使用原生键盘，不向正文追加 `/open`。回归同时覆盖 emoji、标题/链接/强调语法与 QQ 标签，保证原始证据未变。

第三轮只等待用户从详情打开原文、再点“下一条原文”，最多两次回复。北京时间 10:29:37 / 10:29:39 两页各一次 accepted，均为被动回复、带原生键盘、正文无 `/open`；ACK HTTP 200（384 / 325 ms），进程自动退出。用户明确确认“按钮和原文都正常”。没有重发报告、改动工作项状态或写 GitHub。脱敏记录见 [m5-qq-retests-2026-11-03.json](evidence/m5-qq-retests-2026-11-03.json)。特殊 Markdown 字符的任意组合仍仅有本地回归覆盖，不扩大客户端确认范围。
