## 关键故障与恢复证据

1. 同事件重放 100 次：一条源事件、一条投影、一条 outbox、一份首次 admission job，内部 ID 保持一致。
2. 非法事件/跨来源/重复 ID 内容冲突：整批失败，其他新事件与 cursor 不推进。
3. 在 cursor 写入、outbox 派发和 batch job 写入处注入 SQLite 错误：关联状态整体回滚，去除故障后可恢复。
4. 真实启动并强制终止 Node 子进程，分别覆盖未提交事务、已提交事件、未 flush segment、已领取任务；重开文件库 quick_check=ok，未提交数据回滚、已提交数据留存、租约与批次恢复无重复。
5. 两个连接竞争领取、过期旧 token、心跳、有限重试、取消、分 lane 并发均通过。外部任务不会因租约过期或普通失败重新发送；待对账状态可见。
6. 不同线程/独立对象保留不同 segment；同源可合批计算；跨来源/跨项目不合批。上下文重用不增加 candidate 次数，截断保留计数与原文。
7. 连续相关消息超过 maxWait 仍 flush；归档消息可以受审计地重新进入候选；编辑/删除追加历史并安排 replay，乱序事件不覆盖较新投影。
8. urgent 仅生成快速分析批次，不创建 P0 事件或发送任务。quiet/maxWait/urgent 的时间边界通过注入时钟验证，没有假称等待了真实平台的 60/120/5 秒。

## 10,000 条合成消息

文件数据库中提交 10,000 条独立事件，其中 100 条明确反馈、9,900 条明确闲聊；保留默认 2% 抽检。

| 本次观测 | 结果 |
| --- | --- |
| 原始事件 / Admission 决定 | 10,000 / 10,000 |
| 入库阶段 | 635 ms；没有启动 Agent job |
| 入库 + 筛选 + 批次入队 | 4,352 ms |
| 审计抽样 / 新候选 | 204 / 304 |
| 生成的完整 Agent 任务 | 11，全部 pending |
| 待派发 outbox / open segment | 0 / 0 |
| 每批上限 | 候选 ≤30，上下文 ≤50 |
| 外部操作记录 | 0 |

另一个全部可执行的 1,000 条反馈突发场景生成 34 批，候选引用恰好 1,000 条，没有重复计数。

完整 Agent 没有安装执行器，因此 304 条候选仍计入 pendingAnalysis。这证明本地采集与后续推理排队解耦，不代表已经完成反馈理解、Issue 聚类或报告生成。

## 验收边界与下一阶段

未接入 QQ/Discord/Steam 真实账号，未调用 GitHub 或 LLM；规则筛选召回率、语义分段质量、模型费用和最终通知送达尚未验证。Linux CI 尚未远端运行。数据库只在本地，仓库未配置远端，所有包保持 private。

对象乱序/同时间修订冲突保留协调记录，尚未安装自动协调器；生产备份/历史数据升级、内容保留与合法删除流程仍需运维和领域阶段验收。当前不是多机服务发布。
