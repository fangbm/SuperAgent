# ADR 0011：独立反馈的 primary 证据

日期：2026-11-03。状态：提示词修订和本地回归已采用；真实模型计数修复复测待完成。

真实 QQ 批处理验收中，两条独立的 Windows 联机崩溃报告被模型提取到同一个 Bug。第一条标为 primary，第二条误标为 corroboration，因此两份原文均保留，但依据冻结契约计算的独立反馈数只有 1。

领域层只统计 primary 对应的独立来源对象。这一边界保持：不能为了增加数量，自动将所有 corroboration 或上下文升级成独立反馈。模型角色判断有误，应修正提取，而不是放宽来源、原文或计数约束。

提取提示明确要求：同一问题的每条独立候选反馈都保留为 primary，可放入同一项目的多个 primary 锚点，也可拆成多个项目后匹配。问题相同不能作为降为 corroboration 的理由；普通闲聊、问题和仅有上下文不能因此计数。默认管线版本升为 `triage-v2.2`，显式任务版本仍被保留。未指定版本的旧重试任务优先复用已持久化的 analysis_requests 管线身份，避免升级引发修订冲突；只有全新的分析请求使用新默认。历史批次不自动重分析，prompt 变化会改变模型请求缓存 hash。

没有修改冻结 contracts、Schema、SDK、默认配置或数据库迁移。原有一次性任务、证据校验、原文和历史提取结果不改写。新增回归证明重分析可使一个 Bug 的独立反馈从 1 修正为 2，不把第三条上下文计数，不产生第二个 Issue，并保留首轮提取及所有源事件。

真实 QQ 输入的数据库已通过 SQLite backup API 创建副本，再进行有限重分析。模型服务连续返回 HTTP 503，原任务进入 dead_letter；冷却后的最后一次独立重分析仍返回 503。未伪造成功结果或手工升级证据角色，因此不能宣称新提示词已经通过真实模型计数验收。见 [群消息主链路验收](../QQ-MAINFLOW-ACCEPTANCE.md)。
