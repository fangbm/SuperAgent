# ADR-0002：M1 本地持久化处理链路

日期：2026-11-02。状态：已采用。

## 决策

采用当前 Node 24 自带的 `node:sqlite`，避免 Windows 上额外编译原生依赖；全部数据库操作为同步、有界调用。固定 WAL、FULL synchronous、外键和 busy timeout。该驱动在当前目标版本仍属开发中的 API，升级 Node 时须重跑文件数据库与进程恢复测试。[Node 24.4 SQLite 文档](https://nodejs.org/download/release/v24.4.0/docs/api/sqlite.html)

保留 v0.9 的五份 SQL 原文作为生产迁移链前缀，新增 006。runner 去除脚本独立的事务包装，在同一事务应用 SQL 和写入 SHA-256 迁移账本；未知既有数据库、缺失/更改的迁移历史直接拒绝。M0 的类型、SDK、Schema、fixtures 与默认配置保持原冻结值。

将队列抽为 `job-queue`，避免 Core 与 buffer 循环依赖。每次领取分配新租约 token；旧 worker 即使名字相同也不能确认新租约。只有本地幂等任务允许租约过期后重领。外部发送/同步任务过期或失败转 dead_letter，并标记需要对账，不宣称已对外投递，也不自动重发。

会话边界以线程、可解析回复链及独立对象身份确定，不根据时间或词相似自动合并讨论。为了降低完整 Agent 启动数量，同来源、同策略的多个独立 segment 可以进入一个计算 batch；segment 身份与原始事件仍分别保留。模型如何从多个 segment 提取 Bug/建议属于 M3。

Admission 使用可解释的确定性规则：只明确的闲聊/空内容直接归档，并按持久事件 ID 和策略版本稳定抽检；未知的实质文本仍保留为候选。`needs_context` 以候选处理，避免短反馈永久滞留。筛选质量尚未进行真实标注集评估。

## 恢复边界

本地 tick 将一段有界 admission 的状态变化与确认同事务提交。batch、segment 封闭、事件映射和 triage job 原子提交。下一次 tick 根据数据库中的截止时间恢复扫描，不依赖丢失的内存定时器。

这是单机 Host 的运行模型。SQLite 序列化写事务与队列租约已验证，不承诺多机集群部署。生产备份、数据保留与导出流程仍须在运维阶段完善；不要将非托管历史库直接指向本服务。
