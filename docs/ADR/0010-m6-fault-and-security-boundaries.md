# ADR 0010：M6 故障恢复与权限边界

日期：2026-11-03。状态：已采用，本地故障注入与回归通过。

M6 审查现有 QQ、模型、GitHub 和 Web 的失败路径，不以真实平台上的破坏性故障代替可重复验证，也不扩大采集或发送权限。

## 修复

1. QQ Gateway 等待 Host 提交时，原串行 Promise 队列没有长度上限。新增内部 `maxPendingDispatches` 选项，默认 256，包含当前正在提交的任务。达到上限时断开并报告覆盖缺口，等待已开始的提交结束，再从已提交序号恢复。尚未开始的队列项不推进 checkpoint；不声称 QQ 可以补齐平台已无法重放的历史。
2. Delivery 原来只在构造时验证收件人绑定。现在每次发送前同时检查数据库绑定与当前授权。绑定变化或被删除时记为 blocked，在调用插件和读取发送凭据前停止；不将旧投递转移到新收件人。
3. GitHub Sync 原来的租约恢复 SQL 扫描整个 external_operations。现在只恢复自己 repository 对应的 external_operation_payloads；QQ、状态动作以及其他仓库的账本由各自 Host 处理。
4. Web 访问密钥轮换原来没有撤销既有会话。现在账号更新与该账号会话删除同属一个事务，密钥发生变化才撤销。相同密钥重启保留会话，其他账号不受影响；角色与项目权限仍在每次请求时重查。该规则不更改 QQ 导航令牌、证据游标或其既有有效期。

## 保持的契约

没有改动 M0 冻结文件、Schema、SDK、默认配置或迁移。网关上限是平台内部可选参数。所有 workspace 包仍为 private，Core 与连接器依赖方向不变。

外部写入结果未知时不盲目重发。QQ 的发送、撤回与业务动作账本独立；半日报保留规则不变。模型可重试的请求仍受任务预算、超时和租约控制，失败不能删除原始入库证据。

验证矩阵和真实平台覆盖边界见 [M6 验收](../M6-ACCEPTANCE.md)。
