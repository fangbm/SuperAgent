# ADR 0009：QQ 状态操作回发原卡片并撤回过时卡片

日期：2026-11-03。状态：已采用；本地检查通过，真实平台按轮次验收。

QQ→GitHub 的首次真实按钮联调已经完成关闭和重新打开，但动作回复先发送静态“等待 GitHub 确认”，完成后没有更新提示。用户要求成功后回发同一 Bug 页面、保留内容和位置并更新状态按钮，同时撤回过时卡片。

## 状态卡片

新按钮使用 Host 私有 qq_action 令牌，包裹原有一次性 status_action 令牌和当前报告修订、路线、成员位置。领域动作仍验证并消费原令牌，未更改 StatusCommand 或冻结 SDK。成功回执通过原上下文重新渲染同一反馈卡，摘要、封存原文和分页位置保留，当前状态标记与允许的动作按钮更新。旧 status_action 按钮仍可解析。

正常启动器先执行 GitHub worker 的一次处理，再刷新尚未进入 durable outbox 的动作回复计划。只有命令成功且远端已读回确认时才显示更新后的状态卡片。已进入 outbox 的请求和历史消息不改写，避免更改幂等身份。若本轮仍待确认、unknown 或需人工复核，提供“查看结果”按钮；该按钮绑定原操作者、项目和命令，只读已有结果，不重新提交 GitHub 操作。读角色不会通过结果页获得写按钮。

## 过时卡片

QQ 官方私聊撤回接口为 DELETE `/v2/users/{openid}/messages/{message_id}`，仅允许撤回机器人自己发送且未超过两分钟的消息。适配器提供 Host 私有可选方法，仍只读取现有 DeliveryPluginHost 的授权秘密，不接触数据库或领域实现；冻结 SDK 不增加接口。

用户随后要求覆盖所有交互，并明确“半日报不删”。Host 从成功、已受理的 outbox 取得机器人自己的 provider message ID，按插件、项目、收件人及绑定隔离。新的消息发送成功后，清理该范围内旧交互消息，包含相同版本重复查询、Bug/建议内容卡、列表、原文分页、Steam 页面与操作提示；不再要求工作项相同或版本升高。时间相同时按实际发送尝试顺序判断新旧。

定时半日报、`/reports` 与“返回半日报”生成的消息均永久保留，不参与撤回。新报告仍可替换旧交互页面。报告页通过 Host 私有 retainMessage 标记保护，历史报告通过目的及已存请求标题保护；此前已排队但未发送的报告撤回任务也会被阻止。玩家自己的消息不在发送账本内。撤回仅影响聊天中的机器人展示，数据库原文、封存报告与审计均保留。新消息发送 unknown 时保留旧消息；两分钟外记录 expired，不调用撤回接口。

撤回有独立持久化账本和租约，每条旧消息最多调用一次 DELETE。HTTP 200/204 受理计为 succeeded；失败单独记录，超时或崩溃窗口为 unknown，不自动重发，也不重做业务操作。每次调用前重核对收件人绑定和账号访问权限。旧卡仍可见时，其旧状态按钮也受一次性令牌和工作项版本校验保护。

## 兼容与验证

追加迁移 010 创建初版状态卡账本；迁移 011 追加 qq_sent_messages 和 qq_message_retirements，扩展到所有交互并原样继承已有撤回结果及未知状态，避免升级后重复调用。未修改已有迁移、external_operations 的冻结 kind 枚举、报告 seal、contracts、SDK、Schema、fixtures 或默认配置。M5 启动器在迁移前备份既有数据库。qq-write 关闭时不发送或撤回消息；撤回调用不计入消息发送条数，另有持久化计数。

测试覆盖原位置/原文保留、成功后按钮切换、未确认不报成功、只读查询与权限、outbox 请求身份不变、生产 tick 的确认/发送/撤回顺序、新卡 unknown 不删旧卡、两分钟窗口、相同版本及不同类别页面替换、半日报保留、旧报告撤回任务被阻止、迁移继承撤回结果、撤回 unknown/崩溃恢复不重试，以及绑定变更阻止调用。平台受理和客户端实际撤回分别验收，见 M5 验收记录。
