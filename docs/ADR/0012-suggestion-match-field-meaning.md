# ADR 0012：建议匹配的相同点与区别字段

日期：2026-11-03。状态：已采用，本地检查与保存的真实 QQ 样例的真实模型复测通过。

重分析同一条建议时，模型返回 same_request，却把“证据相同、请求结果一致”的说明放进 distinguishingDetails。Host 将非空区别视为需复核的信息，因此保守地创建待复核候选并保留旧空对象。这一现象在两次独立真实模型复测中复现。

修订仅澄清模型输入：matchingOutcome/rationale 承载相同点和判断理由；conflictingRequirements 只放实际冲突；distinguishingDetails 只放影响同一性判断的实际区别或关键信息缺失。相同证据、相同结果、标题换句话说不是区别；不存在区别时用空数组。

不在 Host 中识别或删除“看起来是相同”的自由文本，不忽略非空区别，不放宽证据校验或人工复核条件。具有真实区别的 same_request 仍然阻止自动关联。旧的待复核副本和历史记录不自动更改。

管线号保持 triage-v2.2；这是既有匹配语义的输入说明修正。运行时 Schema 的结构和字段不变，仅增加 description；请求 hash 同时包含 Schema 和提示词，不会把旧匹配缓存当作新结果。未修改 M0 冻结契约、Schema 文件、SDK、默认配置或数据库迁移。

新增本地回归验证：重分析标题改写但证据相同的建议复用原工作项，不重复计数或错误要求复核；存在真实区别时仍创建待复核候选且不能进入自动同步。

最终独立副本使用同一批真实 QQ 样例，三次真实模型调用完成：Bug 原对象的独立反馈为 2，建议原对象的有效反馈为 1，建议匹配返回 same_request、冲突和区别均为空；总 Bug 行与建议行各 1，无待复核或重复建议。源事件、首轮提取、旧失败任务与基线库均保留，QQ/GitHub 写入为 0。本轮先后两次复测合计 6 次调用。完整检查 219 项 Node 测试、6 组参考验证通过。见 [主链路验收](../QQ-MAINFLOW-ACCEPTANCE.md)。
